# 直播笔记的稳定标识与音频引用

每个学习单元、知识组、词条和例句都有独立的稳定 ID。ID 用于界面渲染和内容校验；学习标记仍按原知识组 ID 保存，旧记录无需重置。

- 已有词条和例句的 ID 已写入数据文件。即使 ID 中包含数字，也不要因为重新排序而重编号。
- 新词条和例句应分配新的、全局唯一的小写字母／数字／连字符 ID。显示顺序只由数组顺序决定。
- 新内容的音频引用使用稳定 ID，不再使用词条文字或当前数组位置。
- legacyAudioRef 是已有内容的兼容别名。它固定了旧的 entry/原文字 或 example/原序号，必须保留；移动内容时不能按新位置重写它。
- 修订中文说明、分类或排列不影响日文录音。更改已发布的日文发话时，应新增内容身份和对应引用，保留旧录音与快照绑定；不要把旧引用改绑到另一段话。

validateLiveIdentities 在模块导入／构建时检查唯一 ID、必要字段与音频引用别名。单元计数由实际条目和补充分组自动计算。

播放器使用构建时生成的精简索引，只包含播放地址、提供方、时长和公开的待配音数量。完整的 SHA-256、字节数、来源清单与发布验证保留在原文件中；此优化不改变已发布录音或上传验证。

## 重复原文的展示（适用于所有新增直播单元）

**禁止重复渲染：新知识组默认不显示上方 `source` 引用块。** 原始 `source` 数据照常保存，以便来源核对、音频引用和必要的勘误；学习页面展示词条、读音、中文释义、备注、用法辨析及日中例句。不能依赖日期或 ID 黑名单手工隐藏每一期，也不能通过删除原始数据或关闭音频校验来解决界面重复。

- 手机笔记或漫画原文如果只是重复下方词条、例句和释义，保留为档案，不设置 `source.contextReason`。有用的独立备注、译法、错字和语境信息应先整合到下方卡片。
- 只有原文确实包含下方尚未表达的独立、必要学习语境时，才允许为该组设置 `source.contextReason`，写明保留它的具体教学理由。漫画原图阅读器与引用块的显示规则无关。
- 统一函数 `getVisibleLiveSource` 控制页面和搜索。即使误设了保留理由，如果去掉标点和空白后原文完全由已展示的词条、读音或例句拼成，运行时也会隐藏它；`validateLiveSourcePresentation` 还会在模块导入和构建时拒绝这种错误。
- 旧的9月30日单元中已经审定的25段独立引用保留兼容显示（23段漫画语境和2段手机练习句）。这份历史兼容名单冻结，不允许添加新日期或新的 ID。
- 单元与浏览器回归测试覆盖11月23日的23组、57条表达，以及所有当前和未来登记的单元；桌面与手机页面检查「私には効かない・効き目がない」不出现重复引用，并保留原词条、读音、释义、音频按钮、用法和例句。搜索只索引页面可见的引用。

每次新增或修订「直播条反」时，先遵循上述规则，再执行 `npm run validate:content`、`npm test`、`npm run build` 和 `npm run test:e2e`。全部验证通过后才发布；如果新增朗读内容，同时遵循原有音频待生成清单和发布规则。
