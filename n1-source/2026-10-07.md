## ② IT / AI 输入｜50分钟

### A. 今日主读｜从 Human-in-the-loop 到 Human-on-the-loop：AI开发本身也正在被AI自动化

MONOist 在 **2026年10月7日 07:30** 报道了 ELYZA 推进「再帰的自己改善（RSI：Recursive Self-Improvement）」研究的最新情况。文章指出，AI研究的重点正在从相对单纯的短任务，向 AI for Science、Long Horizon 等需要数小时乃至数日、跨越多个步骤的复杂任务移动。要让AI Agent稳定完成这些任务，仅有基础模型还不够，还需要支撑执行的ハーネス以及用于判断质量的評価機構。

ELYZA把AI参与AI开发的自动化程度整理为四个阶段：`Human-Only → Human-in-the-loop → Human-on-the-loop → Closed loop`。其中 Human-in-the-loop 仍需要人持续参与关键环节；Human-on-the-loop 则更接近“AI持续执行，人负责监督与最终把关”；Closed loop 的目标则是让改善循环本身进一步自动化。报道还介绍，ELYZA已在ハーネス改善中使用自律改善Agent，让AI自己发现表现较差的点并反复修改，从而提高任务性能并降低推理成本。

今天按 **8分钟速读 → 14分钟精读 → 5分钟日语摘要** 的顺序进行。速读只回答四个问题：

`① 基盤モデル、ハーネス、評価機構分别解决什么问题？`  
`② Human-in-the-loop 与 Human-on-the-loop 的核心区别是什么？`  
`③ 为什么“AI能自己改代码”还不能直接等同于安全可靠的RSI？`  
`④ 如果改善循环越来越自动化，工程师应该保留哪些停止、回滚和评价机制？`

精读时优先观察这些表达：`再帰的自己改善 / 自律的に継続する / 多岐にわたる / 評価機構 / 担保する / 完遂する / 改善を繰り返す / ～に加えて / ～に移行する / ～ことで`。这些只是今天的**沉浸观察点**，不是当天 C 的正式新词或新语法，不参与主站的全历史查重。

这篇材料对面试最有价值的一点是：**AI Agent 的能力不能只用“模型聪不聪明”来解释。** 真正落地时，模型之外还有工具使用方式、执行流程、评价基准、失败检测、成本以及人工监督。即使未来AI能持续改进自己的ハーネス，也仍然需要明确什么指标代表改善、谁能批准进入下一阶段、什么时候必须停止。

今天形成一个面试可用观点：

> AIエージェントの性能を高めるには、基盤モデルだけでなく、ツール利用や実行フローを支えるハーネスと、結果を客観的に測る評価機構が必要だと考えています。自動化の範囲を広げる場合でも、人が介入する条件や停止・ロールバックの仕組みを明確にしておくことが重要です。

### B. 补充阅读｜Gemini 从 Gems 转向“Skills”：AI功能也需要版本迁移和生命周期管理｜12分钟

ITmedia エンタープライズ在 **2026年10月7日 07:00** 报道，Google 正在 Gemini 中导入新的「スキル」功能，用来保存并反复调用经常使用的指示，并逐步取代现有的 Gems。Skills 可以通过 `/` 加技能名调用，也可以根据对话自动生成或在条件匹配时自动执行；多个技能还可以组合使用，并支持把文档、PDF、图像等参照文件包含在技能中。

这篇文章最值得工程师注意的不是“又多了一个AI功能”，而是**已有功能会退役，企业必须管理迁移**。报道给出的 Gems 支持结束时间因账户类型而不同：个人账户为2026年11月，Workspace企业及非营利计划为2027年3月，教育机构计划为2027年6月。已有 Gems 会在相应阶段迁移到 Skills，但并不是所有实验性功能都保证自动迁移。

今天只思考一个问题：

`AI製品の機能が頻繁に変わるとき、企業は「使えるかどうか」だけでなく、何を管理すべきか。`

可以从 `inventory / owner / migration deadline / compatibility / test / fallback` 六个角度回答。把它和主读放在一起理解：**AI越来越会自动执行，但产品和平台本身也不断变化，因此自动化越深，版本、依赖、评价和退出路径越重要。**

### 5｜読解：整体观点判断｜改编・对应原题 Q59

AIが自分でコードを書き、評価結果を見て改善を繰り返せるようになると、開発速度は大きく上がるだろう。しかし、改善回数が増えたこと自体を「性能向上」と考えるのは危険である。評価方法に偏りがあれば、数字だけが良くなって実際の利用価値は下がる可能性もあるからだ。

そのため、自動改善を進めるほど、何を成功と定義するのか、どのテストを通すのか、どんな変化なら人が確認するのかを明確にする必要がある。人の作業を減らすことと、人の判断をなくすことは同じではない。

筆者の考えとして最も適切なものはどれか。

① AIが自動で改善できるようになれば、人による評価基準は不要になる。  
② 改善回数を増やすことがAI開発で最も重要な評価指標である。  
③ 自動改善を広げるほど、評価基準と人が介入する条件を明確にする必要がある。  
④ AIの自動改善には危険があるため、研究段階でも利用すべきではない。
