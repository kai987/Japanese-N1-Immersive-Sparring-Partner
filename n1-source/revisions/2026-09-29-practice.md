### IT／AI主读与补充输入

主读沿用原稿引用的TECH.ASCII.jp页面：[Microsoft IQとは？ AIエージェントが必要とする理由は？ マイクロソフトの担当幹部が解説](https://ascii.jp/elem/000/004/437/4437493/)。原稿将报道时间记为2026年9月28日07:30，并转述Microsoft IQ作为企业上下文平台的定位：Agent除了通用模型能力，还需要组织关系、业务状态、内部知识与外部信息。原稿提到的「更好的上下文」观点用于理解信息基础如何影响回答，不据此否定模型能力本身的作用。

速读保留原稿四个问题：高性能模型为何仍可能给出不懂企业业务的回答；Work IQ、Fabric IQ、Foundry IQ、Web IQ分别提供哪类上下文；统一上下文平台如何帮助治理；企业AI Web应用的前端应如何让用户确认Agent使用了哪些依据。原稿对四类上下文的介绍如下，作为历史文章的阅读定位：

| 原稿所列类别 | 原稿记述的上下文重点 |
| --- | --- |
| Work IQ | 员工如何协作。 |
| Fabric IQ | 业务数据的汇集。 |
| Foundry IQ | 企业内部知识库。 |
| Web IQ | 外部最新信息的连接。 |

精读观察 `前提となる／文脈を与える／分散する／統合する／把握する／～に基づいて／漏えいを防ぐ／必要最小限／権限を与える／原因を特定する`。这些是沉浸观察点，不是当天正式新词或新语法。主读后三句日语摘要分别说明「企业上下文缺少什么」「如何在权限范围内提供依据」「用户怎样确认判断所用的信息」。

原稿还转述了治理方面的讨论：企业知识涉及知识产权，取得上下文时需要考虑最小权限、权限管理与信息保护。SCSK案例被描述为利用Fabric IQ整合业务数据后，原需数天才能发现的业绩下降迹象可在下一个营业日检测到，原因分析工作量被报告减少约50%。这些是冻结原稿记载的个案说法，不是本修订重新测得的结果，也不能直接推广为所有组织的收益、统一检测时限或必然改善幅度。

保留原稿的面试思考：RAG／Agent的质量既与模型有关，也取决于context freshness、权限、来源追踪、数据语义与用户确认。前端可以帮助用户查看依据、状态、权限边界和可回退操作。这里是学习者展开架构讨论的方向，不将建议写成所引产品当前已经具备的完整功能清单。
