# Japanese N1 Immersive Sparring Partner

React・TypeScript・Viteで作る、99日間のN1学習アプリです。
UIは日本語、教材の対訳・語義・解説には日本語と中国語を使用しています。

## 開発と検証

Node.js 24を使用します。依存バージョンと `package-lock.json` を管理しています。

```bash
npm ci
npm run dev
```

```bash
npm test                 # 保存データ移行・日付・選択肢・教材取り込み
npm run build            # 型検査・教材検証・本番ビルド
npx playwright install chromium
npm run test:e2e         # 本番プレビューを自動起動してブラウザー検証
```

ブラウザーテストはポート4173を使用し、結果と画像はOSの一時ディレクトリに出力します。
GitHub Pagesのワークフローでもテストとビルドを通してから公開します。

## 学習と記録

- 没入読解は「日本語のみ」「日中対訳」「解説」を切り替えられます。
- 語彙・文法を「要復習」「習得済み」に分類できます。
- 読解は回答後に再挑戦でき、以前の回答履歴を保持します。再挑戦を中断しても前回の結果は残ります。
- 読解の選択肢は日ごとに表示順を変えます。保存には元の選択肢番号を使うため、旧回答の意味を維持します。
- 誤答は復習一覧から問題へ戻れます。再挑戦で正解すると、その問題の自動復習項目が消えます。
- 連続学習日数は、読了・語彙／文法の状態変更・読解回答を行った実際の日付（日本時間）から計算します。当日未学習の場合は昨日までの連続日数を表示します。
- 旧版には実際の学習日付がないため、固定表示されていた「11日」は引き継ぎません。語彙・文法・回答・読了記録は保持します。旧回答の日時は「日付不明」と表示します。
- 記録はこのブラウザーの `localStorage` に保存します。書き込みに失敗しても学習は続行でき、画面の「保存を再試行」で再保存できます。
- 不正な記録は検証して修復します。読み込めた項目は保持し、修復した場合は画面に案内を表示します。

複数端末の同期、復習日の自動通知は未実装です。ブラウザーのサイトデータを削除すると記録は消えます。

## 語彙・文の音声

語彙・読み・連語、文法の例文、没入読解・短文読解の各文、復習用例、複合動詞と直播ノートに再生ボタンがあります。音声はローカルの AivisSpeech で生成した **morioki / ノーマル（497929760）** です。語彙は教材の読みを使い、文章は文ごとに再生できます。再生中のボタンで一時停止・再開し、別の音声やページを開くと前の音声を停止します。

```sh
# AivisSpeech を起動し、指定話者をインストールした状態で実行
npm run audio:generate
# 新規・変更音声は下記の公開手順を完了してから npm run build
```

生成は未生成・変更分だけを処理し、同じ発話を日付やカード順序に依存しないIDで共有します。検証済みMP3は `public/audio/morioki-normal/` にローカルキャッシュとして保存し、Gitには追加しません。公開バイトの検証が完了したキャッシュは削除でき、その後も既存のクラウド音声を再利用します。発話・参照元・音量・長さ・SHA-256は `public/audio/manifest.json`、画面用索引は `src/data/audio-index.json` に保存します。既存音声を検証し、一時ファイルから置換するので途中停止後も再開できます。生成済み音声の再生には AivisSpeech の起動は不要です。

公開音声は `src/data/audio-sources.json` の固定URLから再生します。Japan IT / AI Daily と発話全文・話者・モデル・語速が一致する音声は、既存R2ファイルを共有します。MP3の圧縮率や前後の無音長は共有判定に含めません。残りは既存Supabaseプロジェクトの公開 `n1-audio` バケットに配置します。ファイル名にはバイト列のSHA-256を含めるため、日報側の再生成後も参照先は変わりません。既存の日報・面接音声は移動しません。

```sh
# 日報リポジトリでfetchした固定コミットの索引と、公開音声の全バイトを照合
npm run audio:dedupe -- --daily-repo /path/to/japan-it-ai-daily --verify
npm run audio:stage -- /tmp/n1-audio-storage-plan.json
# 出力フォルダ内のMP3だけを Supabase n1-audio/morioki-normal/ にアップロード
# 全ファイルの公開バイトを検証した後にのみ、再生先索引を原子的に更新
npm run audio:publish -- --plan /tmp/n1-audio-storage-plan.json
npm run audio:validate:remote
```

Supabaseバケットは音声の公開読み取りだけを許可し、一般ユーザー向けのアップロード権限は付けません。管理画面からアップロードでき、秘密キーはフロントエンドに不要です。ビルドは公開済みのローカルMP3を出力から除外します。CIは索引と教材の対応を検証し、`audio:validate:remote` はR2とSupabase上の全音声のサイズ・SHA-256を検証します。ローカルファイルも必須にして検証する場合は `npm run audio:validate -- --local` を使います。

日次教材のPages公開後、`sync-n1-audio.yml` が成功済みの上流R2コミットを固定し、新しい発話の共有音声を取得・ハッシュ・音量・長さで検証して索引に追加します。`src/data/audio-pending.json` に未収録の文と参照元を残し、同じ入力の再実行ではタイムスタンプだけのコミットを作りません。日報音声がN1より後に公開された場合は、既存のローカル日報タスクが音声公開後に同じワークフローを一度呼び出します。手順は [音声同期の契約](docs/automation/README.md#incremental-audio-follow-up) を参照してください。

N1固有の読解文などはローカルAivisSpeechで生成し、未公開分だけをSupabaseへアップロードして全公開バイトを検証します。GitHub Actions単独ではMacのAivisSpeechや管理画面のログインを利用できません。未収録の内容は「音声は準備中です」と表示し、ブラウザー標準の別話者へは切り替えません。中国語訳と画面操作の説明は読み上げ対象に含めません。音声のライセンスは `public/audio/morioki-license.txt` に収録しています。

## 複合動詞のシリーズ

左側の「複合動詞」から、構造・意味ごとの8シリーズを開けます。語彙カードの「複合動詞」ラベルからも対応するシリーズへ移動でき、「元の語彙カードに戻る」で元の日付・カードに戻ります。

- 「～合う」と関連表現
- 時間・期限・数量
- 「～込む」「～出す」「～上げる・～上がる」
- 「～切る・～抜く」「～直す・～返す」
- 「取り～・引き～・差し～」

全ページ共通の上部検索欄で、毎日の教材・複合動詞・直播ノートをまとめて検索できます。結果は種類ごとに表示され、毎日の教材では該当する日付の語彙カード・文法カード・段落へ移動して一致箇所を表示します。日中対訳・解説のヒットは必要な表示モードも開きます。複合動詞を選ぶと対応するシリーズへ移動します。日本語・読み・中国語の意味で検索でき、各語に例文・訳・使い分けを付けています。検索すると一致箇所をハイライトして自動で移動し、検索欄を画面上部に残したまま「上一处／下一处」や検索結果を閉じた状態での Enter／Shift+Enter で一致箇所をたどれます。シリーズを切り替えても検索語を保持し、日本語変換中は自動移動を待ちます。`#compound-verbs/au` などのURLでシリーズを直接開けます。
分類は [国立国語研究所の解説](https://www2.ninjal.ac.jp/vvlexicon/about.html) を参考にしています。「間に合う」「気が合う」は助詞を含む固定表現として区別し、拓展語のJLPTレベルは一律にN1扱いしません。

追加・編集は `src/data/compound-verbs.ts` で行います。カードとの対応は `src/lib/compoundVerbs.ts` の明示的な索引で管理し、単に語尾が一致するだけではラベルを付けません。

## 日次教材の取り込み

既存教材は `src/data/lesson.ts` と `src/data/history-legacy.ts`、新しい教材は
`src/data/daily/YYYY-MM-DD.json` で管理します。構造は [日次教材の仕様](src/data/daily/README.md) を参照してください。

```bash
npm run import:daily -- /path/to/2026-09-10.json
npm run validate:content
npm run build
```

インポートは全体を検証した後、対象日のファイルだけを置き換えます。同じ日を再実行しても教材は増殖しません。不正なファイルで既存教材を上書きしません。

検証内容：必須項目、実在する日付、開始日（2026-08-30）とDayの一致、ファイル名、日付付きID、IDの重複、本文・対訳・解説の段落数、選択肢と正解番号。
同日のJSONは旧教材より優先されます。アーカイブ一覧と検索にも自動で反映されます。

日報の生成元からの取得・生成・Gitへの送信は、このリポジトリには含まれていません。
外部の生成処理がJSONを書き出した後、上記のコマンドで取り込み、変更を `main` にpushすると既存のGitHub Pagesワークフローが検証・公開します。
このコマンド自体はcommit・push・公開を行いません。

## 主な構成

- `src/App.tsx`：画面と学習操作
- `src/components/ReadingExercise.tsx`：回答・再挑戦・履歴
- `src/lib/progress.ts`：旧データ移行・保存データ検証・連続日数
- `src/lib/reading.ts`：選択肢の表示順と元番号の対応
- `src/lib/archive.ts`：教材検証と日付別の統合
- `scripts/import-daily.ts`：検証付きの日次取り込み
- `tests/`：単体・ブラウザー回帰テスト
