# Japanese N1 Immersive Sparring Partner

IT・AIの話題を題材に、読む・語彙を増やす・文法を確認する・復習する学習を続ける、99日間の日本語N1学習アプリです。日本語を中心としたUIに、中国語の対訳・語義・解説を組み合わせています。一部の操作表示・学習ノートには中国語も使用しています。

**[学習アプリを開く](https://kai987.github.io/Japanese-N1-Immersive-Sparring-Partner/)** · [ローカル開発](#ローカル開発と検証) · [教材の同期](#日次教材の同期と取り込み) · [音声の運用・保守](docs/audio-maintenance.md)

React・TypeScript・Viteで実装し、GitHub Pagesで公開しています。学習にはブラウザーを使用し、既存の公開音声を聴くためにAivisSpeechを起動する必要はありません。

## 主な機能

| 機能 | できること |
| --- | --- |
| 没入読解 | 日本語のみ・日中対訳・解説を切り替えて文章を読む |
| 語彙・文法 | 読み、意味、連語、例文、ニュアンス、用法の違いを確認する |
| 読解問題と復習 | 四択問題に回答し、解説の確認・再挑戦・誤答の復習を行う |
| 複合動詞 | 構造や意味ごとのシリーズを開き、語彙カードから関連表現へ移動する |
| 直播ノート | 学習単元・分類・出典の引用をたどり、表現を復習する |
| 全体検索 | 教材・複合動詞・直播ノートを検索し、一致箇所のハイライトとスクロールで探す |
| 音声再生 | 語彙・例文・読解の文などをmoriokiの音声で聴く |
| 学習記録 | 読了、要復習・習得済み、回答履歴、連続学習日数を保存し、バックアップを出力・取り込みする |

教材中の語彙・文法は、出典の実際のレベル表記を保持します。関連表現やIT用語を含むため、すべての項目を一律にN1とは扱いません。

## 学習の進め方と記録

1. 日付を選び、その日の没入読解を読む。
2. 語彙・文法の例文を確認し、「要復習」「習得済み」を記録する。
3. 読解問題に回答し、選択肢ごとの解説を確認する。
4. 誤答復習や関連する複合動詞を開き、必要な表現を繰り返し確認する。

読解は再挑戦しても以前の回答履歴を保持し、中断時にも前回の結果が残ります。選択肢の表示順は日ごとに変わりますが、保存には元の選択肢番号を使います。誤答は元の問題へ戻ることができ、再挑戦で正解すると、その問題の自動復習項目が消えます。

連続学習日数は、読了・語彙／文法の状態変更・読解回答を行った実際の日付（日本時間）から計算します。当日未学習なら昨日までの連続日数を表示します。旧版の固定値「11日」は引き継がず、日時のない旧回答は「日付不明」と表示します。

記録は使用中のブラウザーの `localStorage` に保存します。同じサイトを複数タブで開いた場合は、操作ごとの変更履歴を統合し、別の語彙のマークや回答履歴を互いに上書きしないようにします。公開後も更新前の画面を開いているタブは、再読み込みしてから学習を続けてください。

「学習履歴」（短い表示では「履歴」）の「学習記録のバックアップ」から、「学習記録をエクスポート」でJSONファイルを保存できます。復元するときは「学習記録ファイルを選択」で内容を確認し、「確認して取り込む」を押します。現在のマーク・回答・表示テーマを優先し、足りない記録と回答履歴を追加するため、既存記録は削除しません。語彙・文法・読解・読了・直播ノートの記録が対象です。

タブ間の反映とバックアップは端末内で行い、ファイルや学習記録をサーバーへ送信しません。クラウドや複数端末の自動同期、復習日の自動通知は未実装です。サイトデータを削除すると学習記録も消えるため、バックアップファイルを保管してください。保存に失敗しても学習は継続でき、「保存を再試行」で再保存できます。不正な保存データは検証して修復し、読み込めた項目は保持します。

保存形式、タブ間の統合、容量不足時の動作は [学習記録とバックアップの仕様](docs/learning-records.md) を参照してください。

## 全体検索と複合動詞

上部の検索欄で、毎日の教材・複合動詞・直播ノートをまとめて検索できます。日本語・読み・中国語の意味で検索でき、結果は種類ごとに表示します。複合動詞と直播ノートでは、語句や読みの完全一致を、説明や例文中の一致より先に表示します。

最初は各種類の上位4件までを表示し、種類ごとの件数も確認できます。「查看全部结果」で全種類の一致結果を開き、「收起结果」で元の表示に戻れます。検索結果は上下キーで選択し、Enterで開き、Escで閉じられます。検索用データは検索欄にフォーカスするか検索語を入力したときに読み込み、失敗した場合は入力を保持して「重试加载搜索」で再試行できます。

結果を選ぶと該当する日付の語彙・文法カード、段落、シリーズやノートへ移動し、一致箇所をハイライトします。対訳や解説で見つかった箇所は必要な表示モードも開きます。複合動詞では、検索結果を閉じた状態の Enter／Shift+Enter や「上一处／下一处」で、一致箇所をたどれます。日本語変換中は自動移動を待ち、複合動詞のシリーズを切り替えても検索語を保持します。

左側の「複合動詞」には、構造・意味ごとの8シリーズがあります。

- 「～合う」と関連表現
- 時間・期限・数量
- 「～込む」
- 「～出す」
- 「～上げる・～上がる」
- 「～切る・～抜く」
- 「～直す・～返す」
- 「取り～・引き～・差し～」

語彙カードの「複合動詞」ラベルから対応するシリーズへ移動でき、「元の語彙カードに戻る」で元の日付・カードに戻れます。`#compound-verbs/au` などのURLでも直接開けます。

分類は [国立国語研究所の解説](https://www2.ninjal.ac.jp/vvlexicon/about.html) を参考にしています。「間に合う」「気が合う」は助詞を含む固定表現として区別します。シリーズは `src/data/compound-verbs.ts`、語彙カードとの対応は `src/lib/compoundVerbs.ts` で管理し、単に語尾が一致するだけではラベルを付けません。

直播ノートの語句と例文には安定したIDを付けています。表示順や説明文を変更しても既存の学習記録と音声の参照を保ち、既存音声には互換用の別名を残します。内容を追加・編集するときの規則は [直播ノートの安定IDと音声参照](docs/live-note-identities.md) を参照してください。

## 語彙・文の音声

語彙・読み・連語、文法の例文、没入読解・短文読解の各文、復習用例、複合動詞と直播ノートに再生ボタンがあります。音声はローカルのAivisSpeechで生成した **morioki / ノーマル（497929760）** です。

語彙は教材の読みを使い、文章は文ごとに再生します。再生中のボタンで一時停止・再開し、別の音声やページを開くと前の音声を停止します。未収録のボタンには「音声は準備中です」という説明と「待配音」ラベルを表示します。サイト全体と直播ノートの選択中単元では、未収録件数と公開音声索引の更新日時も確認できます。文字の学習はそのまま続けられ、音声は既定のバックグラウンド時間帯に準備します。ブラウザー標準の別話者へは切り替えません。中国語訳や画面操作の説明は読み上げ対象に含めません。

### 日次の自動処理

日次教材のPages公開後、`sync-n1-audio.yml` が成功済みの上流R2コミットを固定し、Japan IT / AI Dailyと発話全文・話者・モデル・語速などが一致する音声を検証して共有します。日報音声の公開が後になった場合は、既存の日報タスクからも同じ共有音声の同期を続けます。

N1固有の文は、初期設定済みのmacOSバックグラウンドワーカーが生成し、ブラウザーの管理ログインを使わずにSupabaseの公開 `n1-audio` バケットへアップロードします。公開URLはバイト列のSHA-256を含む固定パスで管理し、既存の日報・面接音声は移動しません。MP3はGitに追加せず、ビルドも公開済みのローカルMP3を出力から除外します。

| 項目 | 動作 |
| --- | --- |
| 確認時間 | 毎日11:10〜13:10、日本時間で15分間隔 |
| 確認時刻 | 11:10、11:25、11:40、11:55、12:10、12:25、12:40、12:55、13:10 |
| 当日の停止 | 新教材や未完了音声を検出して処理を始めた後は、その日の追加確認を停止 |
| 時間帯の終了 | 最終確認の分が終わる13:11に処理中でも安全に中断 |
| 翌日の再開 | 未完了の録音・アップロード・検証の進捗を保持し、翌日の時間帯に続行 |
| ログイン・起床・手動確認 | 同じ時間帯・当日制限・OSロックを適用し、時間外のリモート確認は行わない |

対象日日報音声の待機や失敗も当日の再確認は行わず、翌日の時間帯に続けます。Macが停止・オフライン・Keychain未解除の間は処理できません。環境復帰後の次の実行可能な時間帯に再開するため、Macのシステム時刻はAsia/Tokyoに設定します。

生成済み候補とアップロード記録を保存し、各アップロード前に公開バイトを照合して重複を防ぎます。専用アップロード関数はトークン、固定バケット、変更不可のMP3パス、1 MB制限、実バイトのSHA-256を検証します。トークン本体はmacOS Keychainに保存し、フロントエンドやGitに秘密キーを含めません。

共有・独自音声とも検証後に索引へ反映します。自動ワーカーは音声メタデータ4ファイルだけを隔離チェックアウトから通常pushし、正確なコミットのPagesと実際の再生を確認します。`src/data/audio-pending.json` に未収録の内容を残し、アップロードやスナップショットの検証成功だけで全教材の音声が完成したとは扱いません。

### 初期設定と保守

音声の生成・運用にはAivisSpeech、指定話者、Python 3、ffmpeg／ffprobeが必要です。macOSの自動アップロードには、専用Keychainヘルパー・アップロード関数・GitHub認証も事前に設定します。これらは通常の学習やフロントエンド開発には不要です。

```sh
# 初回設定後、または起動設定・bootstrapを更新した後
npm run audio:worker:install
# 時間帯・当日制限を守って一度確認
npm run audio:auto
```

進捗・ログ・録音候補は `~/Library/Application Support/N1 Audio/`、起動設定は `~/Library/LaunchAgents/dev.kai987.n1-audio-worker.plist` に保存します。中断後の再開に必要なため、これらのデータは保持してください。

手動移行、公開音声の検証、明示的に承認された対象日だけの一回限りの修復は [音声の手動移行・保守](docs/audio-maintenance.md) を参照してください。日次の実行条件と公開判定の詳細は [音声同期の契約](docs/automation/README.md#incremental-audio-follow-up) にまとめています。

## ローカル開発と検証

Node.js **24**を使用します。依存バージョンは `package.json` と `package-lock.json` で固定しています。

```sh
git clone https://github.com/kai987/Japanese-N1-Immersive-Sparring-Partner.git
cd Japanese-N1-Immersive-Sparring-Partner
npm ci
npm run dev
```

音声の生成やアップロードを行わずに、既存教材と公開音声で画面を開発できます。通常の開発・再生にSupabaseの秘密キーは不要です。

初期表示には最新教材と日付一覧を読み込み、過去の教材は日付を選んだときに読み込みます。検索索引も検索操作時に読み込み、再生用の音声索引にはURL・提供元・長さ・準備状況に必要な項目だけを含めます。教材や音声の元データを削る変更ではなく、ビルド時には引き続き全教材・出典・音声の完全なメタデータを検証します。

```sh
npm run typecheck         # TypeScriptの型検査
npm run validate:content  # 全教材と取り込みデータの検証
npm test                  # Node.jsとPythonの単体・回帰テスト
npm run build             # 型検査・教材／音声検証・本番ビルド
npx playwright install chromium
npm run test:e2e          # 本番プレビューを自動起動してブラウザー検証
```

`npm test` にはPython 3も必要です。ブラウザーテストは事前にビルドし、ポート4173を使用します。結果と画像はOSの一時ディレクトリへ出力し、既存プレビューと競合する場合は `N1_PREVIEW_PORT` で別ポートを指定できます。

GitHub Pagesのワークフローは、教材・自動同期契約・単体テスト・ビルド・ブラウザーテストを通してから公開し、公開先の対象日も検証します。

## 日次教材の同期と取り込み

教材原稿は `n1-source/YYYY-MM-DD.md`、日次教材は `src/data/daily/YYYY-MM-DD.json`、上流の学習項目・頻度・出典情報は `src/data/it-study-snapshot.json` で管理します。既存の独立教材は `src/data/lesson.ts` と `src/data/history-legacy.ts` に保持します。

通常の自動更新では、原稿・上流の公開コミット・学習スナップショットを固定した `.github/n1-sync-request.json` を、`sync-n1-daily.yml` が検証します。このワークフローが対象日の教材JSONとスナップショットを更新し、Pages公開とオンラインの対象日を確認します。原稿の作成、教材の同期、共有音声、独自音声は、それぞれの進捗と公開結果を区別します。

手動でJSONを取り込む場合は、既存の検証付きインポーターを使用します。

```sh
npm run import:daily -- /path/to/YYYY-MM-DD.json
npm run validate:content
```

インポーター自体はcommit・push・公開を行いません。全体の検証後に対象日のファイルだけを置き換え、同じ日の再取り込みで教材を増殖させません。同日のJSONは旧教材より優先され、日付一覧と検索にも反映されます。

検証では、必須項目、日付とDay、ファイル名、日付付きID、本文・対訳・解説の段落対応、四択の正解番号などを確認します。新学と復習を分け、語彙・文法の実際のレベルを保ち、頻度にはIT日報全体の日付数を使用します。N1計画のDayとIT日報の期号は別の指標です。

構造は [日次教材の仕様](src/data/daily/README.md)、原稿・リクエスト・再開・公開の条件は [自動同期の運用契約](docs/automation/README.md) を参照してください。
